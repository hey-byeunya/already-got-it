## 조사 방법

- `gh pr list --state merged`로 지난 조사 이후 머지분 확인 → PR#12·#13 (PR#10·#11 은 존재하지 않음).

## 지난 조사와 비교해서 뭐가 달라졌나

**1. 지난달 지목한 「없음」 항목은 이번에 메꿔졌다 — 단, 사람이 아니라 조사가 메꿨다**
PR#7(온보딩 투어/힌트 배지)이 두 번의 문서 작업에서도 누락된 채 남아 있었던 것을, 8/31 조사가 직접 채우고 이번 PR#12(`ffa29c9`)로 머지됐다. 지난달 표의 마지막 행("사람이 아니라 이 조사 자체가 직접 채움")이 실제로 배포까지 간 것이다.

**2. 같은 패턴이 세 번째로 재현됐다 — 이번엔 `PRD.md` 에서**
PR#2→PR#3, PR#7→8/31조사 에 이어 `fa40fd8` 이 같은 자리를 반복했다. 다만 양상이 달라졌다: 이번 커밋은 openspec 스펙을 **신설**하고 `docs/manual-qa.md` 까지 스스로 채웠는데, **`PRD.md` 하나만 건너뛰었다.** 「문서를 아예 안 쓴다」에서 「개발 문서는 쓰고 제품 문서를 잊는다」로 옮겨간 셈이다.

**3. 지난달 제안한 PR 체크리스트 / CI 사전 점검은 여전히 미도입 — 두 달 연속 이월**
7/23 에 처음 제안하고 8/31 에 "도입 안 된 걸로 보임"이라 적었는데, 이번에도 그대로다. `fa40fd8` 의 `PRD.md` 누락은 정확히 그 점검이 막을 수 있던 종류다.

**4. 스킬 자신의 드리프트가 다른 형태로 재현됐다**
지난달엔 「하드코딩한 목록이 낡았다」였는데, 이번엔 「목록을 적어두는 방식 자체가 저장소 대부분에서 작동하지 않는다」로 드러났다. 실측 — **git 저장소 18개 중 README 문서 인덱스가 있는 곳은 3개**뿐이다. 발견 절차로 바꾸고 저장소 4곳에서 검증하니 실제 결함 4건이 나왔다: `docs/**` 미탐색(`citecheck` 표면 2→12개) · `git ls-files` 맹신(추적 0건 저장소에서 1→4개) · `.claude/**` 오포함(29→17개) · 인덱스 누락 오탐(6건→2건). 스킬 문서의 사실 오류도 하나 정정했다(「`docs/handoff/**` 는 git 추적 밖」 → 7개가 추적 중).

**5. 이번 조사도 같은 방식으로 이 자리에 온다**
`review/` 에서 초안 5개(PR별 4 + 채점 요약 1)를 만들어 검토하고, 첫 조사·지난 조사와 같은 형식으로 `domain/2026-09-10-pr-doc-matching.md` 로 승격했다. 이번엔 승격 전에 `review/` 초안을 `domain/` 에 먼저 커밋했다가 이름을 다시 쓴 지난 라운드(`bf6b313`→`3c22a72`)의 두 단계를 생략했다.
